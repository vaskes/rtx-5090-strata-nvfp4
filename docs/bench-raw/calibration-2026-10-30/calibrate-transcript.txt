Transcription of the container log of the calibration run of 2026-10-30
(the measurement lines, verbatim; the setup phase before them is elided).

Why a transcription and not the raw file: the first version of
scripts/calibrate.sh ran `setup.py --calibrate` WITHOUT `--no-start`, so the
fork started the serving process after the measurements and the container never
exited; the runner sat in `docker wait` until the container was removed by
hand, and `docker logs` then failed with "can not get logs from container
which is dead or marked for removal". The runner now passes `--no-start`, so a
re-run writes the genuine log. The numbers below are the ones the fork
printed, in its own words.

Reading of the sweep, for the record:
  - PCIe share: the engine's own value on this box is 0.35 and it is also the best
    measured (94.1 tok/s, tied with 0.25). The fork's fallback value 0.55 - the one
    calibrate.py assumes when the engine does not report one - would have cost 23 %.
  - draft floor: 0.7 (the product default) is the best; 0.5 gives -8 %, 0.3 gives -19 %.
  - CPU workers: 10 beats the engine's default 15 by 3.0 % (95.3 vs 92.5 tok/s), which
    is exactly the fork's 3 % threshold, so it was kept. 8 and 4 are worse.
  - expert tier: the engine default (94.1) beats both adaptive variants (86.9 / 88.8),
    so nothing was changed there.
  => the only setting that survived: --pool-workers 10.
